# configs/compliance —— GB 44495 / GB 44496 合规测试配置（知识库 P19 落点）

**定位**：合规验证方向的结构化底座——把两份强制性国标拆成「要求 → 测试方法 → 证据 → 判定」可执行表格，
并提供证据模板与冒烟清单。**本块只做结构与模板，不声称执行过真实合规用例。**

**红线**：纯文档工程；不接触真实车型/ECU；不执行任何真实合规测试。

---

## 1. 两份标准

| 项目 | GB 44495-2024 | GB 44496-2024 |
|---|---|---|
| 名称 | 汽车整车信息安全技术要求 | 汽车软件升级通用技术要求 |
| 核心对象 | 整车的对外接口 / 通信 / 数据 / 身份 / 日志 / 密码 / 软件 / 物理接口 | 软件升级的管理、包安全、流程、回滚、记录 |
| 执行节奏 | 新申请型式批准的车型 **2026-07-01** 起执行 | 同上 |
| 国际对应 | ≈ UN R155 + ISO/SAE 21434 的产品落地条款 | ≈ UN R156 + ISO 24089 |

> **条号纪律**：本目录所有表格的序号仅供表内引用，**不是条款号**。
> 引用到报告/备案材料时必须从正式文本逐条核对，写作 `§[条款号]` 并注明"以正式文本为准"。

## 2. 产出物

| 文件 | 内容 | 用途 |
|---|---|---|
| `gb44495_requirement_matrix.md` | GB 44495 四列表：20 行（8 个维度） | 测试方案骨架 + 判定准则 |
| `gb44496_requirement_matrix.md` | GB 44496 四列表：12 行 + 断电矩阵 | 升级安全测试方案骨架 |
| `evidence_template.md` | 合规测试证据模板（对齐 `reports/EVIDENCE_TEMPLATE.md`） | 每条用例的证据留档格式 |
| `smoke20_checklist.md` | 冒烟 20 项（对齐知识库 10/04 §11） | 拿到平台先做的 20 条检查 |

## 3. 用法

1. **写测试方案**：从两张矩阵挑适用行 → 第 2 列变用例 → 第 3 列定证据文件名 →
   第 4 列写死判定准则（评审后才能开始执行）。
2. **执行**：按 `evidence_template.md` 逐用例留证；本仓可演练的实验台：
   - `labs/vehicle/uds-basic`（诊断认证/权限/种子随机）
   - `labs/vehicle/ota`（包签名/篡改/防降级/分块完整性）
   - `labs/crypto`（SM2/SM3/SM4 + 密钥管理检查表）
3. **报告**：把证据编号回填到矩阵与模板的 §5 条款映射表；
   "不适用"项必须在 §8 给出理由与证据。

## 4. 与知识库 P19 对齐

- P19（`projects/project-19-iso21434-audit/README`）产出差距分析 / 三向映射 / 检查清单 / 证据包规范；
  本目录是其**四列表 + 证据模板**的可执行落点（对应 P19 产出物二与产出物四的前半部分）。
- 知识库 12/04（`12-vehicle-standards/04-GB44495与GB44496合规测试`）给出 18+12 行的方法论拆解；
  本目录在其基础上补齐"证据模板 + 冒烟清单"并落到 SecurityLab 目录。

## 5. 已知局限（如实记录）

1. **未执行真实合规用例**：本块是结构与模板，表格中的判定全部待填；
   没有任何"PASS"结论来自本轮。
2. **条号未逐条核对**：正式引用前必须对照 GB 44495-2024 / GB 44496-2024 正文核对。
3. **本仓实验台只覆盖部分维度**：网关、TLS/PKI、日志、A/B 分区、云端任务等维度在本仓无模型
   （见 `smoke20_checklist.md` 的 NOT_RUN 行）。
